Доклад по лабораторной работе №6: Автоматизированное UI-тестирование (Page Object Model)

Зачем нужна эта лабораторная?

Я изучил, как тестировать графический интерфейс «глазами пользователя». Раньше я мог проверять функции и базы данных, а теперь учусь автоматизировать реальный браузер через Selenium WebDriver. Главная цель - освоить паттерн Page Object Model (POM), чтобы мои тесты не превратились в хаос из поиска кнопок и полей ввода.
------------------------------------------------------------------------------

Что именно делает код?


Код автоматизирует тестирование веб-приложения Simple Calculator на сайте GlobalSQA. Скрипт делает следующее:

Открывает браузер Chrome и переходит по заданному URL.

Вводит два числа в соответствующие поля.

Выбирает арифметическую операцию из выпадающего списка (+, -, *, /, %).

Нажимает кнопку «Go!».

Считывает результат с экрана и сравнивает его с ожидаемым. Если числа совпадают - тест пройден.\
------------------------------------------------------------------------------

Как реализован паттерн Page Object Model (POM)?


В проекте код четко разделен на две части:

Папка pages/ (класс CalculatorPage) - это «карта» страницы. В ней хранятся только локаторы (адреса) элементов и методы для работы с ними (input_first, select_op, click_go).

Папка tests/ (класс TestCalculator) - здесь находятся сами тесты. Они вообще не знают, как устроен HTML этого сайта. Тесты просто вызывают методы из Page Object (например, self.page.input_first(5)).
